## 1. プロジェクト概要（一言で言えると最高）

**「感謝の連鎖を可視化するSNS」**

現代のSNSに蔓延するネガティブな要素（誹謗中傷・炎上）に対して、
「日常の小さな感謝や勇気を投稿し、誰かの行動につながる世界」をコンセプトに開発。

ブロックチェーンの「連鎖・不変性・透明性」という概念をSNSのコンテキストに応用し、
感謝の投稿（Thanks）が次の行動（Action）を生み出し、可視化される仕組みを実装した。

## 3. システム構成

```
ユーザーのブラウザ
    │
    ▼
Vue 3 SPA（Single Page Application）
    │
    ├── Vue Router → ページ遷移（ブラウザのURLを変えてもページリロードしない）
    ├── Pinia/Vuex なし → ref()ベースの軽量グローバルstate
    │
    ▼
Firebase SDK（フロントエンドから直接接続）
    │
    ├── Firebase Authentication → ログイン/ログアウト/ユーザー管理
    ├── Cloud Firestore → データベース（posts / tasks / users コレクション）
    └── Firebase Storage → 画像ストレージ

    ▼
AWS Amplify（ホスティング）
    └── frontend/dist/ を静的配信
```

**バックエンドサーバーは存在しない。**
フロントエンドから Firebase に直接アクセスする、いわゆる **BaaS（Backend as a Service）** 構成。

## 5. 主要機能の説明

### 5-1. ファーストビュー（自分の担当）— ボトルメールUI

**MainView.vue** が担当。海の上をボトルメールが漂う演出。

**仕組み：**
1. Firestoreから感謝投稿（Thanks）を取得
2. ランダムで4件を抽出し画面に表示
3. 各ボトルに固有の色（10色のパレットからランダム選択）を割り当て
4. CSS Animations + JavaScript物理シミュレーションで「海を漂う」演出
5. ボトルをクリック → 下から滑り上がるモーダルで詳細表示

**アニメーションの仕組み（重要）：**
```
bottleJourney  ← ボトルがA地点からB地点へゆっくり移動（35〜55秒）
floatBob       ← 上下に揺れる（6〜11秒）
floatWiggle    ← 左右に揺れる（3〜6秒）
floatRotate    ← 傾いて回転（5〜9秒）
```
これら4つのアニメーションをCSSで同時実行することで「海を漂うボトル」を表現。

**物理シミュレーション（衝突回避）：**
`requestAnimationFrame` を使ったゲームループで、ボトル同士が近づきすぎたら反発力を加える。

### 5-2. 感謝チェーン（ChainView）

感謝の連鎖をツリー構造で可視化。

- 根（root）= Thanks投稿
- 枝（branch）= Action投稿（返信）
- 各ノードをクリックするとポップアップで内容表示
- **Panzoom** ライブラリでズーム・パン操作対応

### 5-3. 投稿システム（2種類の投稿）

| 種別 | 意味 | depth |
|------|------|-------|
| **Thanks** | 感謝の発信（ルート投稿） | 0 |
| **Action** | 感謝に対する行動の返信 | 1以上 |

Actionを投稿すると、自動的に `actionCount` がカウントアップされ連鎖が可視化される。

### 5-4. タスク管理

「後でアクション（Action投稿）する」という予約機能。

1. Thanks投稿を「タスクとして保存」
2. マイページの「つながり」タブに表示
3. Action投稿すると「完了」に移行

### 5-5. 投稿非表示（hidden）

- 特定の投稿を非表示
- 特定のタグ・作者の投稿をまとめて非表示
- ユーザーごとの `hiddenPosts` サブコレクションに保存

### 5-6. いいね（最大10回/ユーザー）

単純な「いいね」ではなく、1ユーザーが最大10回まで押せる仕様。
「どれだけ気持ちが伝わったか」を段階的に表現するUX設計。

## 6. 自分の担当箇所の詳細解説

### ボトルメールUIの実装詳細

**担当ファイル：** `frontend/src/views/MainView.vue`

#### 実装のポイント

**① 4つのCSSアニメーションの合成**

```css
/* ボトル本体（wrapper）は移動+上下揺れ */
animation-name: bottleJourney, floatBob;

/* ボトル画像（img）は傾き */
animation-name: floatRotate;

/* ボトルの子要素は左右揺れ */
animation-name: floatWiggle;
```

各アニメーションの時間をランダム化（`Math.random()`）しているため、
4つのボトルがすべて異なるリズムで動く。

**② CSS Custom Properties（カスタムプロパティ）の活用**

```javascript
// JavaScriptで動的にCSS変数を設定
return {
  '--start-x': `${pattern.startX}%`,
  '--journey-duration': `${journeyDuration}s`,
  '--bob-y': `${bobY}px`,
  // ...
}
```

```css
/* CSSでその変数を参照 */
@keyframes bottleJourney {
  0%  { left: var(--start-x); top: var(--start-y); }
  100%{ left: var(--end-x);   top: var(--end-y); }
}
```

CSS Custom Propertiesを使ってJavaScriptとCSSをブリッジすることで、
JavaScriptでアニメーションのパラメータを計算しつつ、アニメーション自体はCSSで実行。
→ パフォーマンスが高い（メインスレッドをブロックしない）

**③ requestAnimationFrameによる物理シミュレーション**

```javascript
const updateBottlePhysics = () => {
  // ボトル同士の距離を計算
  // 近すぎたら反発力を加える
  bottlePositions.value.forEach((bottle, i) => {
    bottlePositions.value.forEach((other, j) => {
      if (i === j) return
      const dx = bottle.x - other.x
      const dy = bottle.y - other.y
      const distance = Math.sqrt(dx * dx + dy * dy)
      if (distance < MIN_DISTANCE) {
        // 反発力の計算
        const force = (MIN_DISTANCE - distance) / MIN_DISTANCE
        forceX += (dx / distance) * force * REPEL_FORCE
      }
    })
    // CSS変数に反発量を適用
    bottle.element.style.setProperty('--repel-x', `${forceX * 10}px`)
  })
  animationFrameId = requestAnimationFrame(updateBottlePhysics) // ループ継続
}
```

**④ モーダルのドラッグ操作（スマホ・PC対応）**

スマホ：`touchstart / touchmove / touchend`
PC：`mousedown / mousemove / mouseup`

ドラッグして100px以上下に引っ張るとモーダルが閉じる。
モーダルを閉じるUXをネイティブアプリライクに実装。

```javascript
const handleMouseDown = (e) => {
  isDragging.value = true
  touchStartY.value = e.clientY
  // windowにリスナー追加（モーダル外でマウスを離しても検知できるように）
  window.addEventListener('mousemove', handleMouseMove)
  window.addEventListener('mouseup', handleMouseUp)
}

const handleMouseUp = () => {
  // dragDistance > 100px なら閉じる
  if (dragDistance > threshold) {
    closeModal()
  }
  window.removeEventListener('mousemove', handleMouseMove)
  window.removeEventListener('mouseup', handleMouseUp)
}
```

## 7. 状態管理の設計

Vuex / Pinia は**使っていない**。Vue 3 の `ref()` を使った軽量グローバルstate。

```javascript
// store/user.js
export const user = ref(null)
// Firebaseの認証状態が変わったら自動更新

// store/modal.js
export const isPostFormModalOpen = ref(false)
export const replyToPost = ref(null) // 返信先の投稿
```

**なぜPiniaを使わなかったか：**
ハッカソンという時間制約の中で、管理が必要なグローバルstateが「ユーザー情報」と「モーダル状態」だけだったため、Piniaは過剰だと判断。`ref()` のエクスポートで十分な複雑度だった。

## 10. コンセプト整理（面接で話せるように）

**問題意識：**
現代SNSの誹謗中傷・炎上・ネガティブな情報が多すぎる

**解決策：**
感謝という「ポジティブな感情」だけを扱うSNSを作ることで、
日常の小さな勇気や感謝が誰かの行動を動機づける世界を目指す

**技術的こだわり：**
感謝のチェーン（連鎖）をツリー構造で可視化したこと

**審査員フィードバック：**
「世界観は良いが導入がやや分かりづらい」
→ 学び：「世界観設計」と「ユーザー導線設計」は別軸で最適化が必要
